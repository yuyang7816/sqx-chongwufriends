# 服务端功能说明

服务端没有给养宠用户点的页面。它是一直开着的程序：用户端和管理端把「登录、看门店、发朋友圈、岛宅投喂、下单付款」这些请求发给它，它检查是否允许、把结果存进数据库，必要时再去问微信、支付宝、短信这些外面的服务。

可以把它理解成总台。两个前台（用户端、管理端）说的话，都由总台记账，并在需要时给外面的公司打电话。

本地开发数据库配置在 `chongwu-server/sqx-application/src/main/resources/application-dev.yml`。库名是 `chongwujiaopengyou`，导入文件是 `chongwu-server/sql/pet-full-mysql57.sql`。用户、门店宠物、朋友圈、岛宅、商城订单都记在这里。

启动类是 `com.sqx.SqxApplication`。端口是 **9294**，所有接口都在 `/sqx_fast` 下面。接口列表在：

http://127.0.0.1:9294/sqx_fast/doc.html

Redis 写在开发配置的 `redisson` 段，地址是本机 `6379`，库号 `5`。本项目通过 Redisson 使用 Redis，本地联调前要先启动 Redis。`application.yml` 里的 `sqx.redis.open` 主要控制部分旧开关逻辑，不能当成「完全不用装 Redis」。

用户端接口前缀多为 `/app/**`，管理端为 `/admin/**`、`/sys/**`。用户端登录凭证用 JWT；管理端登录和菜单权限用 Shiro。

下面先说它为两个前台做哪些事，再说它会主动连接哪些外面的服务。

## 它为养宠用户做的事

这些都是用户在手机里点一下之后，由服务端完成的：

- **注册和登录**：检查手机号和短信验证码，或检查密码；也支持微信小程序登录。通过后发给用户一张登录凭证（token）。之后需要登录的请求都要带这张凭证，否则视为没登录。
- **找回密码、改资料**：核对短信或原密码，然后改账号资料。
- **探索首页**：按城市返回门店列表、运营 Banner、社群相关入口配置。
- **门店与宠物档案**：返回门店小伙伴列表、宠物详情（品种、标签、介绍等）。
- **宠物朋友圈**：保存动态、评论、点赞、分享记录；支持敏感词校验；接收用户投诉。
- **消息铃铛**：汇总点赞、评论等互动通知未读数与列表。
- **岛宅养成**：返回岛宠状态、亲密度、资产（积分 / 花瓣 / 爱心等）；处理投喂、任务领取、集市购买、常驻宠物设置。
- **退役领养**：返回可领养列表与详情；保存用户提交的领养申请，供管理端审核。
- **人气打榜与助力**：记录打榜、助力行为与榜单数据。
- **养宠攻略**：返回攻略分类与文章内容。
- **商城**：商品分类、SPU/SKU、下单、优惠券核销、积分兑换。
- **支付**：生成支付单；支付结果以微信或支付宝的通知为准，再改订单状态。
- **资产与券包**：查询积分、金币、爱心、券包、兑换记录、助力记录。
- **文件上传**：接收头像、动态图、视频等，再按系统配置存到本机或对象存储。
- **注销**：记下注销申请，交给管理端处理。

## 它为管理端做的事

- 工作人员登录，并按角色限制能看的菜单。登录验证码也由它生成。
- 提供数据看板要用的统计数字。
- 保存城市、门店、宠物品种与档案、社区动态审核、投诉与投诉类型、敏感词。
- 岛宅宠物、任务、集市、投喂订单。
- 领养审核、打榜、攻略分类与文章。
- 商城分类、商品、规格、订单、优惠券发放。
- 支付订单与支付流水查询。
- 用户列表与用户 360（资产、订单、岛宅、券、动态等维度）。
- 首页装修、运营 Banner、系统配置。
- 管理员、角色、菜单、字典。

## 对接了哪些外面的服务

下面每一项都是服务端真的会向外发送请求的。密钥没填时，它不会假装成功，用户端会看到失败提示。

### 短信

注册、验证码登录、找回密码等场景，由服务端发短信。可在系统配置里切换短信服务商（如短信宝、阿里云短信、腾讯云短信）。签名和模板要在对方网站申请。只把程序跑起来，不会自动拥有短信额度。

### 微信支付

用户选择微信支付时，服务端用商户号和密钥向微信支付下单，并把拉起支付需要的信息交回手机。支付完成后，微信访问服务端的通知地址，服务端核对之后，再把订单改成已支付。

还需要微信公众平台上的小程序 AppId：https://mp.weixin.qq.com/ 。商户平台在 https://pay.weixin.qq.com/ 。

### 支付宝

和微信同一类流程：下单、拉起支付宝、等待支付宝通知。需要支付宝开放平台的应用编号和密钥：https://open.alipay.com/ 。

### 图片 / 文件存储

用户和管理端上传的图片、视频由服务端接收，然后按「系统配置」保存：

- 本机硬盘（未配对象存储时的常见方式）
- 阿里云 OSS：https://www.aliyun.com/product/oss

对象存储密钥没配好、本机上传目录也不可写时，上传接口会失败。

### 微信登录

用户端微信一键登录依赖小程序 AppId / AppSecret 等配置。没配时，微信登录会失败，但仍可用手机号密码或验证码登录（验证码仍依赖短信）。

## 这些不是外面的公司

- **余额 / 积分 / 金币支付或兑换**：主要改数据库里的资产数字。
- **岛宅投喂、任务、集市、打榜助力**：业务记在自己的数据库里。
- **朋友圈点赞评论、投诉**：在自己的数据库里。
- **领养申请**：只生成待审核记录，审核在管理端完成。
- **操作日志、权限、角色**：只约束管理端工作人员。

## 两个前台怎样和它配合

用户端和管理端都不直接保存订单和审核结果。它们把请求发给服务端，服务端再决定要不要去问微信、短信或图床。

所以：

- 服务端没启动时，两个网站都能打开界面，但登录、列表、付款都会失败。
- 外面的密钥只配在服务端能读到的「系统配置」里。只在用户端页面上改文字，不会变成已经开通了微信支付。
- 管理端改完门店、商品、Banner、攻略并保存后，用户端下次请求才会看到新内容。
